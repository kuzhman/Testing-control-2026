# Testing-control-2026
Testing & Control 2026 — мобильное PWA Готовый проект на основе исходного HTML: 25 компаний (в исходном файле фактически 25, включая 9 в разделе «Остальные»). Сохранены стенды, категории, сайты, email и исходная группировка. Для каждого стенда можно создать любое число независимых записей. Что уже работает - Мобильный интерфейс, поиск, фильтры, добавление компании, отдельные записи и действия. - IndexedDB: заметки, оценки, фото (с уменьшением до 1800 px), локальная работа без сети. - PWA с иконкой и service worker; установить через меню браузера «Добавить на главный экран». - Автоматическая синхронизация каждые 15 секунд при открытом приложении, при возврате на вкладку и появлении сети. Фоновая синхронизация при полностью закрытом приложении не гарантируется. - Экспорт XLSX, ZIP (включая фотографии) и резервной копии JSON без внешних библиотек и интернета. Развёртывание GitHub Pages 1. Создать репозиторий и загрузить содержимое этой папки в его корень (включая supabase/). 2. Settings → Pages → Deploy from a branch → main / (root). Дождаться ссылки https://<имя>.github.io/<репозиторий>/. 3. Открыть ссылку на телефоне в Chrome, добавить приложение на главный экран. Перед поездкой открыть его один раз с интернетом. 4. Для синхронизации настроить Supabase ниже. Пока Supabase не настроен, приложение работает локально, но два телефона не синхронизируются. Supabase (обязательно для совместной работы) 1. Создать проект Supabase. В SQL Editor выполнить supabase/schema.sql. 2. Установить Supabase CLI, войти в аккаунт и привязать проект (supabase login, supabase link --project-ref <project-ref>). 3. Установить секрет TC_SHARED_CODE длиной минимум 12 символов: supabase secrets set TC_SHARED_CODE='очень-длинный-случайный-код'. 4. Развернуть функцию из корня проекта: supabase functions deploy sync --no-verify-jwt. Функция сама проверяет общий код на сервере. Не помещайте service_role ключ в браузер или GitHub. 5. На обоих телефонах открыть «Экспорт» и указать одинаковые: https://<project-ref>.supabase.co, публичный anon / publishable ключ из настроек Supabase, общий код. Нажать «Сохранить подключение». 6. Проверить: создать запись на телефоне №1, дождаться «Синхронизировано», открыть приложение на телефоне №2 и дождаться появления записи. Важные ограничения текущей версии - Общий код доступа хранится в localStorage каждого телефона. Это удобная схема для двух доверенных устройств, не система персональных прав. Любой обладатель кода сможет получить данные. Используйте случайный код, не публикуйте его и при компрометации смените секрет на сервере. - Нет принудительной блокировки конкурирующего редактирования одной и той же записи. Для одновременных заметок создавайте разные записи: они не конфликтуют. Одновременное редактирование одной записи может привести к перезаписи последним запросом. - Данные в облаке и на телефонах; браузер может очистить локальные данные. Делайте ZIP-резервные копии. - Облачный экспорт гарантирует полноту только после успешной синхронизации обоих телефонов. - При очень большом числе фотографий полный обмен может быть медленным: текущая версия использует полный опрос записей, а не инкрементальную синхронизацию. - Для открытого браузера 15-секундный опрос; при закрытии приложения синхронизация ждёт следующего запуска. - При удалении фото запись в облаке остаётся как tombstone для согласованности. - Это первая рабочая сборка, не проверенная на реальных двух устройствах и живом Supabase. Перед выставкой обязателен тест с отключением сети и последующим восстановлением. Локальный просмотр Для разработки можно запустить python -m http.server 8000 в папке проекта и открыть http://localhost:8000. Для установки PWA с другого устройства нужен HTTPS-хостинг.
